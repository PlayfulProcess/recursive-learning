# A game round

The order is the point: educational, then engaging, then beautiful. Every round is checked in
that order, and every round is seen before it is described.

## 0. Look before touching

1. Start the static server (`.claude/launch.json` → `game-worktree`, port 8094) and open the page
   in the Browser pane at 1280×900 and at 375×812. Screenshot both; read them. If the pane cannot
   draw (a hidden pane times out), use `get_page_text` and `read_page` instead of guessing.
2. Read the last critique or the user's screenshot literally: where did their finger go, and what
   did the page do? A first-timer presses the brightest button. Whatever they press must answer
   in words, near the button, within one screen.

## 1. One change set

- Change `game/*` only. The landing is generated by `scripts/build-site.mjs`; edit the script,
  then run `node scripts/build-site.mjs`. Never touch other repos from this chat.
- The model lives in `game/walk-model.js` and is shared by both walk pages. Do not change it in a
  visual round. The `window.walk` contract (`state`, `priors`, `simulate`, `stepOnce`, `makeRng`,
  `ENDPOINTS`) stays intact; other pages embed it.
- Text edits to the page go through a Python script written with the Write tool (heredocs break
  on apostrophes and curly quotes). Assert each replacement matches exactly once.
- Card art: public-domain only, fetched through `https://commons.wikimedia.org/wiki/Special:FilePath/<file>?width=480`.
  Never the full Commons file — one of them is 15,000 px wide and freezes a phone. Every image is
  credited at the foot of the page.
- No emoji anywhere. The mark is the spiral (`scripts/mark.svg`).
- Never change the deck grammar (`0489bd30…`) unless this chat is the named deck writer for the
  week; never publish anything; no stakes, no leaderboards, no claim that the numbers forecast.

## 2. Verify, in this order

1. `node -e` parse of the page's script (a stray comment once swallowed a closing brace).
2. Reload with a cache-busting query (`?v=N`); the deck JSON can be served stale — check
   `performance.getEntriesByType('resource')` or fetch with `cache:'reload'`.
3. Console errors: none.
4. Fixed seed: `walk.simulate(walk.state, {...walk.priors, seed:1}, 4000).probs` at the defaults
   reads Adolescence .683, Lock-in .053, Doom .264. If it moved, the model moved — stop.
5. Do the thing a first-timer does, through the tools (`form_input` on a slider, click Step,
   click a card), and read the sentence the page wrote back. Then the phone.

## 3. Ship

- Commit from the worktree, rebase on `origin/main`, push to `main`. Message file first
  (`$TEMP/msg.txt`), never inline.
- Wait for Pages the way a browser will see it: poll a PLAIN request (no cache headers) with a
  new random query each time (`?q=$RANDOM$RANDOM`) until it contains a string only the new
  version has. A `Cache-Control: no-cache` poll passes minutes earlier than the edge actually
  serves the new copy to browsers, and the query string does not defeat the edge cache; two
  playtesters played the old page because of this. Then report
  with the live links: `https://learning.recursive.eco/game/spread.html`, `/game/index.html`, `/`,
  and the deck `https://recursive.eco/view.html?id=0489bd30-d71d-4b7b-82b2-662bcbef25b0`.
- End with a phone checklist: tap X → expect Y, five to seven lines.

## 4. The clueless playtester

After every shipped round, launch one agent (model opus, no context from this chat) with only
the live URL and this brief: "You are a first-time visitor who knows nothing about this page.
Open it in the Browser pane, at phone width too. Play for a few minutes the way a curious
stranger would: press whatever looks pressable first. Do not read the source. Report in plain
words: what you thought it was, what you pressed first and what happened, where you got lost,
whether you could say the one idea in one sentence, and one thing you would tell a friend."
Launch it only after the poll above has passed, with a query string nobody has fetched before
(`?v=<short sha>-<random>`), and tell it which visible string proves the new version.
Put its report in the round's summary, unedited in substance, and treat its confusion as the
next round's first item.
